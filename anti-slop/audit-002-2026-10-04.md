# Audit responsif HATO dev dan perbandingan dashboard prod

4 Oktober 2026. Pemeriksaan read-only, sebelum push. Tidak ada perubahan UI, submit formulir, migrasi, deployment, atau penulisan database dalam audit ini.

## Kesimpulan

UI belum siap dipush sebagai perbaikan responsif. Masalah utama bukan halaman meluber secara horizontal, tetapi breakpoint yang tidak memperhitungkan sidebar, angka keluar dari kartu, header terjepit, serta modal/menu yang tidak tahan terhadap jendela pendek.

Dashboard produksi adalah referensi visual yang lebih tepat untuk preferensi pengguna: informasi jadwal, varian produk, rotasi, dan kas dikelompokkan dengan jelas. Backend dan kontrak dev tetap dipertahankan; jangan mengembalikan implementasi backend prod atau angka stok teoritis hanya untuk meniru tampilannya.

Metode: audit teknis Impeccable, antislop core/UI/layoutmobile/human, inspeksi source, DOM dan screenshot browser Chrome. Ini bukan workflow dual-agent `$impeccable critique` dan bukan sertifikasi aksesibilitas menyeluruh.

## Lingkungan dan batas bukti

- Dev: `http://localhost:3000`, server yang sudah berjalan; tidak dihentikan oleh audit.
- Prod: `https://hato-zeta.vercel.app/`, dashboard dibaca sebagai referensi, tanpa submit aksi.
- Perbandingan dashboard memakai Minggu 3 - Sep 2026 yang sama: 3 pesanan, nilai Rp 212.000, pembayaran Rp 171.000, sisa Rp 41.000.
- Dashboard diukur pada lebar 320, 390, 640, 767, 768, 900, 1023, 1024, 1280, 1440 CSS px. Screenshot terpisah dikonfirmasi pada 320, 768, 1024. Pengukuran beruntun bukan bukti screenshot semua ukuran.
- Halaman lain diuji secara terarah pada 320 dan/atau 768/1024; bukan matriks semua halaman di semua ukuran.
- Menu diperiksa pada 390 x 500; modal produk pada 390 x 500 dan 740 x 350.
- Tampilan awal sesaat setelah navigasi kadang masih loading/hidrasi. Temuan data memakai state setelah pemuatan, bukan snapshot awal kosong.
- Native Expo, HP fisik, keyboard virtual, 200% zoom, kontras seluruh pasangan warna, profiling performa, dan submit mutasi tidak diuji.
- Detector `.agents/skills/impeccable/scripts/impeccable.cmd detect --json src` mengembalikan `[]`, exit 0. Detector bersih tidak membatalkan kegagalan browser di bawah.

## Temuan berprioritas

### 1. [P1] Breakpoint sidebar membuat konten mendadak menyempit

Lokasi: `src/components/AppShell.tsx:89,93`; `src/app/orders/page.tsx:226,236`; `src/app/cycles/page.tsx:125`; `src/app/inventory/page.tsx:170`; `src/app/page.tsx:227,235`.

Bukti: lebar viewport 767 menghasilkan main sekitar 761 px. Pada 768, main menjadi sekitar 506 px karena sidebar 256 px muncul. Grid `sm`/`md` tetap aktif karena mengikuti viewport, bukan ruang konten. Kartu pesanan pada 768 hanya sekitar 226 px; header pesanan memecah deskripsi menjadi lima baris dan tombol menjadi dua baris. Metrik barang menjadi empat kartu sempit.

Dampak: memperbesar jendela justru membuat UI lebih sempit dan sulit dibaca. Ini cocok dengan gejala pengguna saat menggeser ukuran window.

Perbaikan: sidebar compact atau drawer pada tablet, expanded hanya ketika ruang cukup; gunakan container query atau breakpoint yang dihitung dari ruang main. Header menumpuk saat kontrol tidak muat, bukan mengorbankan judul. Grid kartu punya lebar minimum yang realistis.

Aturan: R-03, C-4. Perintah terkait: `$impeccable adapt`.

### 2. [P1] Nilai Rupiah terpotong di laporan dan menimpa kartu peringkat

Lokasi: `src/app/reports/page.tsx:684`; `src/app/ranking/page.tsx:118,165`.

Bukti: Keuangan & Margin pada 1024 memakai lima kolom di area main sekitar 762 px. Screenshot menunjukkan Rp 2.237.000 dan Rp 2.116.000 keluar/terpotong dari kartu. Podium pada 768 memakai tiga kolom; area isi kartu sekitar 100 px dan footer nilai belanja menimpa kartu berikutnya. Root scroll width tetap tidak lebih besar dari viewport.

Dampak: angka operasional tidak dapat dibaca utuh meskipun pemeriksaan overflow halaman tampak bersih.

Perbaikan: grid minmax/auto-fit dengan minimum isi kartu, susun footer podium vertikal ketika sempit, jangan truncate nominal uang; uji Rp 1.000.000 sampai nominal panjang tanpa mengganti data produksi.

Aturan: R-03, R-35, C-4. Perintah terkait: `$impeccable adapt`.

### 3. [P1] Menu mobile bagian bawah tidak terjangkau pada window pendek

Lokasi: `src/components/AppShell.tsx:192`.

Bukti: pada 390 x 500, bagian bawah link Peringkat & Skor berada di y=558. Panel fixed setinggi sekitar 515 px dimulai di bawah header, tanpa batas tinggi/scroll internal (`overflow-y: visible`).

Dampak: navigasi bawah keluar dari layar; scrolling halaman tidak menyelesaikan panel fixed yang tidak scrollable.

Perbaikan: batas tinggi `calc(100dvh - header)` dan scroll internal, pengelolaan fokus/menu yang jelas; verifikasi height 350/500 dan landscape.

Aturan: R-03, R-26, C-4. Perintah terkait: `$impeccable adapt`.

### 4. [P1] Semantik dan focus trap Modal terpasang pada backdrop, bukan panel

Lokasi: `src/components/ui/Modal.tsx:68-79`.

Bukti source: `panelRef`, `role=dialog`, `aria-modal`, dan `aria-labelledby` ditempatkan pada div backdrop kosong dengan `aria-hidden=true`. Panel yang berisi judul dan isi adalah sibling-nya. Pada rincian piutang, Tab dari Tutup modal keluar menuju Next.js Dev Tools; focus trap tidak menahan fokus karena mencari kontrol pada backdrop kosong.

Dampak: pengguna keyboard keluar dari dialog; struktur dialog tidak merepresentasikan konten untuk assistive technology. Ini bukan klaim sudah diuji dengan screen reader fisik.

Perbaikan: pindahkan ref dan atribut dialog ke panel, backdrop hanya untuk dismissal; kelola background inert, fokus awal, trap Tab/Shift+Tab, Escape dan return focus. Migrasikan modal custom ke primitive yang sama.

Aturan: R-26, R-32, C-4. Perintah terkait: `$impeccable harden`.

### 5. [P1] Modal produk terpotong pada landscape pendek

Lokasi: `src/app/products/page.tsx:391`; pola serupa di `src/app/members/page.tsx:670,804` (risiko source, clipping hanya dikonfirmasi langsung pada modal produk).

Bukti: pada 740 x 350, modal produk memiliki top -61 dan bottom 412. Overlay `overflow-y: visible`; screenshot berikutnya mengonfirmasi judul di atas viewport dan footer di bawah viewport. Pada 390 x 500 form produk dan anggota masih muat, sehingga masalah tergantung tinggi, bukan hanya lebar.

Dampak: tombol tutup/submit bisa tidak terlihat pada window pendek. Tidak dilakukan submit.

Perbaikan: max-height berbasis dvh, panel scrollable, header/footer tetap bisa dijangkau; satukan semua modal setelah primitive diperbaiki.

Aturan: R-03, C-4. Perintah terkait: `$impeccable adapt`.

### 6. [P1] Mode read-only belum terlihat konsisten pada kontrol

Lokasi: `src/app/page.tsx:221`; `src/app/inventory/page.tsx:117-119,173`; `src/app/cycles/[id]/page.tsx:128,170,202,208`.

Bukti: banner menyebut aksi operasional dinonaktifkan. Input pesanan dashboard tetap tampak aktif, tetapi tombol pada halaman Pesanan disabled. Simpan draf barang, Simpan harga, dan Konfirmasi dan kunci rekap masih tampak aktif; source handler kembali langsung ketika `canMutate` false. Source dan state tombol diperiksa; tombol simpan tidak diklik. Form tambah produk/anggota juga masih terbuka tanpa penjelasan read-only di form.

Dampak: aplikasi menjanjikan aksi yang tidak tersedia, memberi kesan tombol rusak atau data gagal disimpan.

Perbaikan: capability yang sama mengendalikan tombol dan input, alasan disabled dekat kontrol, tetap izinkan melihat detail. Banner cukup ringkas: mode baca-saja dengan detail teknis terpisah. Jangan menghapus guard backend.

Aturan: R-26, R-27, C-4. Perintah terkait: `$impeccable harden`.

### 7. [P2] Dashboard dev kehilangan pengelompokan informasi yang disukai di prod

Lokasi: `src/app/page.tsx:196-270`.

Bukti: prod mempunyai header siklus compact, tiga tahap tanggal, rincian varian di quota, card rotasi, card billing dan alur mingguan. Dev mengganti tanggal dengan satu paragraf, quota menjadi dua agregat, dan memberi ruang besar pada narasi Langkah berikutnya. Varian/stok tidak lagi ada di dashboard. Ini kehilangan visibilitas, bukan klaim datanya hilang dari database.

Dampak: dashboard dev kurang mendukung pemindaian operasional cepat. Kelompok kas dan rotasi terasa kurang tegas karena tidak memiliki containment setara prod. Preferensi pengguna pada prod didukung perbedaan komposisi nyata.

Perbaikan: kembalikan struktur prod sebagai referensi visual, gunakan data/kontrak dev. Header minggu + timeline compact; quota dengan varian; rotasi pada kolom utama; kas/alur sebagai kartu pendamping pada layar lebar, stack pada tablet/ponsel. Tampilkan stok hanya jika sumber dan status kepastiannya jelas. Prod sendiri bukan acuan kebenaran semua label: sidebar prod masih menyebut Minggu 2 saat pilihan dashboard Minggu 3, dan label hari pembukaan tidak sesuai tanggal.

Aturan: C-1, C-4; R-17 untuk kepastian data. Perintah terkait: `$impeccable layout`.

### 8. [P2] Padding quota mobile hilang dan header dashboard melompat pada 1024

Lokasi: `src/app/page.tsx:101-126,196-232`.

Bukti: pada 320, header quota memakai padding tetapi panel Ayam/Tahu dan progress bar menempel tepi card. `TargetPanel` baru mendapat horizontal padding pada `sm`; wrapper mobile adalah `contents`. Pada 1024, header berubah menjadi row, tombol Input pesanan menyempit menjadi sekitar 109 x 58 px dan label dua baris. Pada 768, unit dan badge quota terpecah beberapa baris.

Dampak: tampilan terasa tidak konsisten saat resize meski tidak ada page overflow.

Perbaikan: satu gutter card pada semua ukuran, divider sesuai orientasi, toolbar tidak shrink di bawah lebar minimum; stack ketika ruang tidak cukup.

Aturan: R-03, C-4. Perintah terkait: `$impeccable layout`.

### 9. [P2] Empty state rotasi saling bertentangan; next action tidak memeriksa siklus closed

Lokasi: `src/app/page.tsx:88-99,246`.

Bukti browser: Minggu 3 menampilkan 0 dari 0 anggota, Semua anggota giliran sudah memesan, dan Belum ada anggota yang dijadwalkan sekaligus. Source nextAction memeriksa draft lalu rekap/penerimaan, tetapi tidak memeriksa closed. Rekomendasi untuk closed adalah risiko source yang perlu dimasukkan ke regression test.

Dampak: tidak ada jadwal disajikan seperti keberhasilan; siklus historis berpotensi memberi instruksi operasional aktif.

Perbaikan: kondisi scheduled > 0 sebelum klaim semua selesai; empty state tunggal dengan konteks. Closed menampilkan ringkasan historis dan piutang, bukan saran input baru.

Aturan: R-27, R-17, C-4. Perintah terkait: `$impeccable harden`.

### 10. [P1] Katalog memakai minggu lain dari konteks kerja yang dipilih

Lokasi: `src/app/products/page.tsx:217-218,246-264`.

Bukti: URL dan sidebar dev memakai Minggu 3, tetapi katalog menampilkan Harga Siklus Aktif: Minggu 4 - Sep 2026 dan link batch menuju Minggu 4 tanpa query cycleId. Katalog mengambil activeCycle dari produk pertama, bukan siklus konteks kerja.

Dampak: pengguna bisa salah mengira harga yang dibaca/diedit milik minggu yang sedang dipilih. Audit tidak mengubah harga.

Perbaikan: satu sumber konteks minggu; tampilkan selector dan label ruang lingkup harga secara eksplisit. Jika katalog memang global, pisahkan data produk global dari harga per minggu dan pertahankan query konteks saat navigasi.

Aturan: C-4, R-26; standar konsistensi konteks. Perintah terkait: `$impeccable harden`.

### 11. [P2] Kontrol lama belum mengikuti sistem yang sama

Lokasi: `src/app/members/page.tsx:410,605,670-787`; `src/app/products/page.tsx:391`; `src/app/reports/page.tsx:311-374`; `src/app/ranking/page.tsx:233` dan filter di bawahnya; `src/components/AppShell.tsx` pada login.

Bukti: input form anggota 34 px, tombol Batal/Tambahkan 32 px pada 390. Filter peringkat 28 px pada 320; tab laporan 34 px. Kartu sub-grup menggunakan generic/div clickable (source tanpa keyboard role/tabIndex). Pada 320 badge jumlah sub-grup mencapai x=342, di luar area kanan viewport. Form login masih mendapat shell/banner operasional setelah hidrasi.

Dampak: target sentuh kecil, cara membuka detail tidak seragam, dan login terasa seperti halaman operasional. Scroll horizontal lokal tabel katalog/komunitas memang dibatasi container dan bukan bug page overflow; tetapi belum menjadi card mobile seperti arah DESIGN.md.

Perbaikan: gunakan primitive bersama untuk kontrol dan modal; target sentuh minimal 44 sesuai R-03; link/button semantik untuk detail; wrap header struktur; shell khusus login. Tentukan kolom prioritas/kartu mobile untuk tabel, jangan mengecilkan semua teks.

Aturan: R-03, R-26, R-32, C-4. Perintah terkait: `$impeccable adapt`, `$impeccable harden`.

## Penilaian terbatas

| Theming/konsistensi | 2/4 | Emerald/slate konsisten secara umum, tetapi primitive custom dan shared berbeda; dark theme bukan scope |
| Integritas implementasi UI | 2/4 | Konteks katalog, aksi read-only dan empty state tidak konsisten; detector 0 tidak mendeteksinya |
| Performa | Tidak dinilai | Tidak ada profiling/bundle/timing yang memadai dalam audit ini |

Tidak diberikan total /20 atau rating rilis karena dimensi performa dan cakupan aksesibilitas tidak lengkap.

Yang sudah baik: data semua halaman utama dan lima subtab laporan dapat dibaca; state disabled utama Pesanan/Buat siklus/Buka-Tutup siklus sudah ada; angka dev pada dashboard sama dengan prod untuk siklus yang dibandingkan; identitas emerald/slate masih terjaga; tabel horizontal dibatasi container sehingga tidak memperlebar halaman.

## Urutan perbaikan yang disarankan

1. `$impeccable adapt`: shell/sidebar, minimum lebar panel, header, grid angka, menu dan modal berdasarkan tinggi viewport.
2. `$impeccable harden`: Modal semantik/fokus, konteks minggu, read-only, empty state dan siklus historis.
3. `$impeccable layout`: pulihkan komposisi dashboard mendekati prod tanpa rollback backend atau kepastian data palsu.
4. `$impeccable polish`: satu putaran konfirmasi terarah pada semua route setelah batch perbaikan.

Acceptance criteria: tidak ada angka terpotong/menimpa; header dan kontrol terbaca pada 320/390/640/767/768/900/1023/1024/1280/1440; menu/modal terjangkau pada height 350/500; Tab/Shift+Tab terperangkap dalam dialog dan Escape/return focus bekerja; konteks minggu konsisten; aksi read-only disabled dengan alasan; dashboard tetap menampilkan informasi prioritas seperti prod dengan sumber data yang valid.

Anggaran verifikasi tahap fix: satu batch browser semua route + satu putaran konfirmasi setelah perbaikan; jika muncul persoalan schema/data baru, laporkan terpisah dan jangan memperluas menjadi migrasi produksi.
